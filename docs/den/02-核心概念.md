# 核心概念详解

Den 有四个核心概念，每个负责一个正交的关注点：

| 概念 | 英文 | 作用 | 定义位置 |
|------|------|------|----------|
| **实体** | Entity | 声明*什么东西存在* | `den.hosts`、`den.homes`、`den.schema` |
| **方面** | Aspect | 声明*什么行为适用* | `den.aspects` |
| **策略** | Policy | 声明*实体如何关联* | `den.policies` |
| **管道/怪癖** | Quirk/Pipe | 方面之间的结构化数据流 | `den.quirks` |

这四个概念的关系：

- **实体**定义数据（存在什么）
- **方面**定义行为（做什么）
- **策略**定义拓扑（如何关联）
- **管道**定义数据流（如何共享）

> Den 本质是一个**数据转换管道**。它接收你的基础设施实体声明，应用方面函数（由策略驱动），最终产生 NixOS/Darwin/Home Manager 的模块配置。

---

## 实体（Entities）

### 什么是实体

**实体**是类型化的数据记录——一台机器、一个用户、一个独立的家庭环境。实体声明了你的基础设施中*存在什么*。

### 三种内置实体类型

#### 主机（hosts）

**`den.hosts`** 以 `<system>.<name>` 为键。每个主机根据其平台自动产生相应的 flake 输出：

```nix
den.hosts.x86_64-linux.igloo = {
  # 此主机的配置
};
```

系统架构自动决定类（class）：

| 架构 | 自动类 |
|------|--------|
| `x86_64-linux`、`aarch64-linux` | nixos |
| `x86_64-darwin`、`aarch64-darwin` | darwin |

如需覆盖，可以显式设置：

```nix
den.hosts.x86_64-linux.igloo.class = "darwin";  # 强制为 Darwin
```

#### 用户（users）

用户**不是**顶级实体——它们在主机内部声明：

```nix
den.hosts.x86_64-linux.igloo.users = {
  alice = {};
  bob = { classes = [ "homeManager" "hjem" ]; };
};
```

每个用户自动获得一个同名的方面（`den.aspects.alice`、`den.aspects.bob`）。

#### 家庭环境（homes）

**`den.homes`** 用于独立于主机的家庭管理器配置（例如在无法获得 root 权限的机器上）：

```nix
den.homes.aarch64-darwin.alice = {};
```

### 自由格式属性

实体类型使用 `freeformType`，所以你可以附加任意数据而无需事先声明选项：

```nix
den.hosts.x86_64-linux.igloo = {
  gpu = "nvidia";
  datacenter = "eu-west";
  monitoring = {
    enable = true;
    alertEmail = "admin@example.com";
  };
};
```

这些属性在方面中通过上下文参数访问：

```nix
den.aspects.igloo.includes = [
  ({ host }: lib.optionalAttrs (host ? gpu) {
    nixos.hardware.nvidia.enable = true;
  })
];
```

### Schema：实体类型的共享选项

`den.schema` 让你为*每一种*实体定义共享选项：

```nix
{
  # 为所有主机启用 Home Manager 集成
  den.schema.host.home-manager.enable = true;

  # 为所有用户添加自定义选项
  den.schema.user = { lib, ... }: {
    options.sshKey = lib.mkOption {
      type = lib.types.str;
      default = "";
    };
  };

  # 在所有实体类型之间共享
  den.schema.conf = {
    options.copyright = lib.mkOption {
      default = "Copy-Left";
    };
  };
}
```

### 严格模式

默认允许自由格式属性。启用严格模式后，所有实体属性必须通过 schema 声明：

```nix
den.schema.host.strict = true;

# 现在这会产生求值错误（gpu 未声明）：
# den.hosts.x86_64-linux.igloo.gpu = "nvidia";
```

### 实体之间的关系图

```
den.hosts
  +-- x86_64-linux
  |   +-- igloo (class: nixos)
  |   |   +-- users
  |   |       +-- alice (classes: [homeManager])
  |   |       +-- bob   (classes: [homeManager])
  |   +-- server (class: nixos, no users)
  +-- aarch64-darwin
      +-- macbook (class: darwin)
          +-- users
              +-- alice (classes: [homeManager])

den.homes
  +-- aarch64-darwin
      +-- bob
```

## 方面（Aspects）

### 什么是方面

**方面**是 Den 的核心创新。它是一个可组合的配置单元，将多个 Nix 类（nixos、darwin、homeManager 等）的模块打包在一个属性集中。

```nix
den.aspects.gaming = { host, user }: {
  nixos = { pkgs, ... }: {
    programs.steam.enable = true;
    hardware.opengl.enable = true;
  };
  homeManager = { pkgs, ... }: {
    programs.mangohud.enable = true;
  };
  includes = [ den.aspects.performance ];
};
```

一个方面 = 一个关注点 = 所有平台。

### 方面的四种形态

#### 1. 静态方面（Static）

纯属性集，没有函数包装。始终包含，不管上下文如何：

```nix
den.aspects.firewall = {
  nixos.networking.firewall.enable = true;
};
```

#### 2. 参数化方面（Parametric）

一个函数，其参数决定了在什么上下文中激活：

```nix
# 只在 {host} 上下文中激活
den.aspects.networking = { host, ... }: {
  nixos.networking.hostName = host.hostName;
};

# 只在 {host, user} 同时存在时激活
den.aspects.user-groups = { host, user, ... }: {
  nixos.users.users.${user.userName}.extraGroups = [ "wheel" ];
};

# 只在 {home} 上下文中激活
den.aspects.shell-config = { home, ... }: {
  homeManager.programs.zsh.enable = true;
};
```

**函数参数形状就是条件判断**——不需要 `mkIf`，不需要 `enable` 标志。Den 的管道在求值时自省函数参数，只在上下文满足时才调用。

#### 3. 前置方面（Forward）

通过 `provides` 将配置从一个实体传递到另一个实体：

```nix
den.aspects.tux = {
  # tux 用户向 igloo 主机提供配置
  igloo.nixos.services.ssh.enable = true;
};
```

跨实体路由现在内置于管道中，无需额外电池。

#### 4. 条件方面（Conditional）

通过策略效果有条件地包含：

```nix
den.schema.host.includes = [
  (den.lib.policy.when ({ host, ... }: host.wsl.enable)
    den.policies.wsl-support)
];
```

### 方面的结构

一个方面有三个组成部分：

#### 自有配置（Owned Configurations）

直接按类设置的配置：

```nix
den.aspects.igloo = {
  nixos.networking.hostName = "igloo";
  darwin.nix-homebrew.enable = true;
  homeManager.programs.vim.enable = true;
};
```

#### 包含（Includes）

形成依赖图——方面可以包含其他方面：

```nix
den.aspects.workstation = {
  includes = [
    # 静态：无条件应用
    { nixos.programs.vim.enable = true; }

    # 参数化：上下文匹配时才应用
    ({ host, ... }: { nixos.time.timeZone = "UTC"; })

    # 引用其他方面
    den.aspects.dev-tools
    den.aspects.gaming
    den.batteries.primary-user
  ];
};
```

#### 提供（Provides）

在方面内部定义的命名子方面：

```nix
den.aspects.igloo = {
  gpu = { host, ... }:
    lib.optionalAttrs (host ? gpu) {
      nixos.hardware.nvidia.enable = true;
    };

  networking = {
    nixos.networking.firewall.enable = true;
  };
};

# 子方面可以这样访问：
# den.aspects.igloo.gpu
# den.aspects.igloo.networking
```

### 方面解析

方面通过 `den.lib.aspects.resolve` 为特定类解析：

```nix
module = den.lib.aspects.resolve "nixos" den.aspects.igloo;
```

解析过程会：收集所有 `nixos` 属性、递归遍历 `includes`、应用参数化分发、去重，最终产生一个包含所有 NixOS 配置的模块。

### `__functor` 模式

Den 利用 Nix 的 `__functor` 特性让方面可调用：

```nix
let
  counter = {
    value = 42;
    __functor = self: n: self.value + n;
  };
in counter 8  # => 50
```

每个 Den 方面都有一个默认的 `__functor`，检查上下文参数以决定产生什么输出。

## 类（Classes）

### 什么是类

**类**是 Nix 模块求值域。Den 本身不定义类——它利用 Nix 生态中已有的类。

### 内置类

| 类名 | 说明 | 来源 |
|------|------|------|
| `nixos` | NixOS 操作系统配置 | NixOS |
| `darwin` | macOS Darwin 配置 | nix-darwin |
| `homeManager` | 用户级 Home Manager 配置 | home-manager |
| `user` | OS 用户账户配置（便捷类） | den.batteries.os-user |
| `os` | 跨平台主机配置（同时转发到 nixos + darwin） | den.batteries.os-class |
| `wsl` | WSL 配置 | den.batteries.wsl |
| `hjem` | hjem 家庭环境 | den.batteries.hjem |
| `maid` | nix-maid 家庭环境 | den.batteries.maid |

### 自定义类

通过 `den.batteries.forward` 可以创建自定义类：

```nix
den.batteries.forward {
  each = lib.singleton user;
  fromClass = _: "myClass";
  intoClass = _: host.class;
  intoPath = _: [ "some" "option" "path" ];
  fromAspect = _: user.aspect;
};
```

> **类 vs 实体类型**：不要混淆。类（`nixos`、`darwin`）是 Nix 模块求值域；实体类型（`host`、`user`、`home`）是 Den 数据类型。类决定了哪个模块系统来求值配置，实体类型决定了策略如何分发。

### 扁平形式（Flat Form）的类模块

Den 方面中的类模块可以写成同时接收 Den 上下文和 NixOS 模块参数的扁平形式：

```nix
den.aspects.my-aspect = {
  nixos = { host, config, pkgs, ... }: {
    networking.hostName = host.name;
    environment.systemPackages = [ pkgs.hello ];
  };
};
```

这里 `host` 是 Den 上下文参数，`config`、`pkgs` 是 NixOS 模块系统参数。Den 的管道会自省函数参数，将上下文值预应用，然后把剩余参数交给模块系统。

> **重要**：扁平形式必须包含 `...`，因为 NixOS 模块系统会传递额外的参数（`config`、`options`、`lib`、`pkgs` 等）。如果没有 `...`，会导致求值错误。

## 策略（Policies）

### 什么是策略

**策略**定义了实体之间的关系——从一种实体类型分叉到另一种，丰富上下文，路由内容。策略是 Den 管道的**骨架**。

```nix
den.policies.host-to-users = { host, ... }:
  map (user: policy.resolve.to "user" { inherit host user; })
    (lib.attrValues host.users);
```

### 策略图

```
flake -> flake-system -> host ---> user
                         |
                         +---> hm-host ---> hm-user
                         |
                         +---> home
```

每个箭头是一个策略。管道在求值时遍历这个图：从根开始，对每个活动策略检查当前上下文是否满足其参数需求，处理返回的效果，然后递归到解析目标。

### 常见效果类型

策略函数返回一个效果列表。效果构造器位于 `den.lib.policy`：

| 效果 | 作用 |
|------|------|
| `policy.resolve bindings` | 丰富当前范围或创建子实体 |
| `policy.resolve.to kind bindings` | 为特定实体类型创建子范围 |
| `policy.include aspect` | 向当前解析注入一个方面 |
| `policy.exclude aspect` | 从当前范围移除一个方面 |
| `policy.route spec` | 在范围之间路由类内容 |
| `policy.provide spec` | 直接将模块交付给一个类 |
| `policy.instantiate entity` | 请求管道后实例化 |
| `policy.pipe.from name stages` | 对怪癖数据应用管道转换 |

### 丰富 vs 实体解析

`policy.resolve` 的行为取决于绑定内容：

```nix
# 丰富——给当前上下文添加 myFlag，不创建新范围
policy.resolve { myFlag = true; }

# 实体解析——创建一个子 "user" 范围
policy.resolve.to "user" { inherit host user; }
```

### 策略激活

声明策略只是**注册**它。要激活，需要在 `includes` 中包含：

```nix
# 为所有主机激活
den.schema.host.includes = [ den.policies.my-policy ];

# 为特定方面激活
den.aspects.igloo.includes = [ den.policies.my-policy ];

# 全局激活
den.default.includes = [ den.policies.my-policy ];
```

### 条件策略

```nix
# 只对特定实体
den.schema.host.includes = [
  (den.lib.policy.for den.hosts.x86_64-linux.igloo
    den.policies.igloo-specific)
];

# 基于条件判断
den.schema.host.includes = [
  (den.lib.policy.when ({ host, ... }: host.wsl.enable)
    den.policies.wsl-support)
];
```

## 管道/怪癖（Pipes/Quirks）

### 什么是管道/怪癖

**怪癖（Quirk）** 是方面发出的结构化数据，注册在 `den.quirks` 中。**管道（Pipe）** 是一种策略效果，用于路由、过滤、转换或聚合怪癖数据。

它们解决的问题：多个方面如何贡献结构化数据给一个消费者？

没有怪癖的情况下，方面之间共享数据的唯一方式是通过 NixOS 模块选项。这会造成耦合：

```nix
# 没有怪癖——紧耦合
den.aspects.nginx = {
  nixos.networking.firewall.allowedTCPPorts = [ 80 443 ];
};
den.aspects.postgres = {
  nixos.networking.firewall.allowedTCPPorts = [ 5432 ];
};
```

有了怪癖，生产者不需要知道消费者：

```nix
# 有怪癖——解耦
den.aspects.nginx = {
  firewall = { ports = [ 80 443 ]; };
};
den.aspects.postgres = {
  firewall = { ports = [ 5432 ]; };
};
```

### 三个角色

| 角色 | 谁 | 做什么 |
|------|----|--------|
| **生产者** | 任意方面 | 在命名怪癖键上发出数据 |
| **架构师** | 策略作者 | 声明管道和路由（`pipe.from`） |
| **消费者** | 类模块 | 通过函数参数接收聚合数据 |

### 如何使用

#### 1. 声明怪癖

```nix
den.quirks.firewall = {
  description = "防火墙端口声明";
};
```

#### 2. 产生数据

```nix
den.aspects.nginx = {
  nixos.services.nginx.enable = true;
  firewall = { ports = [ 80 443 ]; };
};
```

#### 3. 消费数据

```nix
den.aspects.networking = {
  nixos = { firewall, lib, ... }: {
    networking.firewall.allowedTCPPorts =
      lib.concatMap (f: f.ports or []) firewall;
  };
};
```

`firewall` 参数接收当前范围中所有怪癖值的列表。如果没有生产者发出数据，它为空列表 `[]`。

#### 4. 带管道路由

```nix
den.policies.filter-tcp = { host, ... }:
  let inherit (den.lib.policy) pipe; in
  [ (pipe.from "firewall" [
      (pipe.filter (e: e.proto == "tcp"))
    ])
  ];
```

### 范围模型

怪癖数据默认为**范围本地**。每个实体（主机、用户、家庭环境）有自己的范围，范围内的生产者贡献到该范围的池子中。

**向上流动**（`pipe.expose`）：子范围的数据可以向上流动到父范围。

**跨范围收集**（`pipe.collect`）：从满足条件的兄弟范围收集数据。

**重命名**（`pipe.as`）：在别名下交付数据，创建派生怪癖。

**其他阶段**：`pipe.for` 完全替换基础值集，`pipe.withProvenance` 为值附加来源作用域 ID。

## 电池（Batteries）

**电池**是 Den 内置的可复用方面。

### 系统电池

| 电池 | 作用 | 默认 |
|------|------|------|
| `den.batteries.hostname` | 从主机声明自动设置主机名 | 选入 |
| `den.batteries.define-user` | 创建 OS 用户账户 | 选入 |
| `den.batteries.primary-user` | 赋予管理员权限 | 选入 |
| `den.batteries.user-shell` | 设置登录 shell | 选入 |
| `den.batteries.os-class` | 跨平台 `os` 便捷类 | 自动 |
| `den.batteries.os-user` | OS 用户便捷类 | 自动 |
| `den.batteries.mutual-provider` | 主机<->用户双向配置 | 选入 |
| `den.batteries.host-aspects` | 主机方面投射到用户 | 选入 |
| `den.batteries.tty-autologin` | TTY 自动登录 | 选入 |
| `den.batteries.vm-autologin` | VM 自动登录 | 选入 |
| `den.batteries.wsl` | WSL 支持 | 条件自激活 |
| `den.batteries.forward` | 自定义类工厂 | 选入 |
| `den.batteries.import-tree` | 传统模块递归导入 | 选入 |

### 家庭环境电池

| 电池 | 作用 |
|------|------|
| `den.batteries.home-manager` | Home Manager 集成 |
| `den.batteries.hjem` | hjem 集成 |
| `den.batteries.maid` | nix-maid 集成 |

### 包管理电池

| 电池 | 作用 |
|------|------|
| `den.batteries.unfree` | 允许特定 unfree 包 |
| `den.batteries.insecure` | 允许特定不安全包 |

### 使用模式

```nix
# 全局默认
den.default.includes = [
  den.batteries.define-user
  den.batteries.hostname
];

# 特定方面
den.aspects.alice.includes = [
  den.batteries.primary-user
  (den.batteries.user-shell "zsh")
];

# 所有用户
den.schema.user.includes = [
  den.batteries.mutual-provider
];
```

## 命名空间（Namespaces）

命名空间允许你从外部来源导入和使用方面：

```nix
den.namespace "community" [ inputs.community-aspects ];

# 然后使用
den.aspects.my-host.includes = [
  <community/niri>    # 角度括号语法
  den.ful.community.hyprland  # 等价形式
];
```

这实现了 Den 的核心社会目标——分享和复用方面。

## 角度括号语法（Angle Brackets Syntax）

Den 提供了一种便捷语法 `<path>` 来引用深层嵌套的方面和 provides：

```nix
# 等价写法
den.aspects.laptop.includes = [
  den.aspects.tools.editors
  den.aspects.alice.work-vpn
  den.batteries.primary-user
];

den.aspects.laptop.includes = [
  <tools/editors>
  <alice/work-vpn>
  <den.batteries.primary-user>
];
```

需要在模块参数中添加 `__findFile`：

```nix
{ den, __findFile, ... }: { ... }
```

并通过设置启用：

```nix
{ _module.args.__findFile = den.lib.__findFile; }
```

## 概念关系总结

```
+--------------------------------------------------------------------+
|                        Den 管道                                     |
|                                                                    |
|  +----------+    +----------+    +---------------+                  |
|  |  实体     |    |  策略     |    |   方面         |                  |
|  | (数据)    |--->| (拓扑)   |--->| (行为)        |                  |
|  |          |    |          |    |  +---------+  |                  |
|  | hosts    |    | resolve  |    |  | nixos   |  |                  |
|  | users    |    | include  |    |  | darwin  |  |                  |
|  | homes    |    | route    |    |  | hm      |  |                  |
|  +----------+    +----------+    |  | hjem    |  |                  |
|                                  |  | maid    |  |                  |
|  +----------+                    |  | ...     |  |                  |
|  |  怪癖     |<-------------------|  +---------+  |                  |
|  | (数据流)  |    管道效果         +---------------+                  |
|  |          |                                                       |
|  | firewall |    +----------+                                       |
|  | backups  |    | 电池      |                                       |
|  | prefs    |    | (预置)   |                                       |
|  +----------+    +----------+                                       |
|                                                                    |
|                      v                                              |
|              +---------------+                                      |
|              | NixOS/Darwin  |                                      |
|              | /HM 输出      |                                      |
|              +---------------+                                      |
+--------------------------------------------------------------------+
```

1. **实体**（数据层）定义存在什么——主机、用户、家庭环境
2. **策略**（拓扑层）定义实体如何关联——主机到用户、主机到 hm-host、丰富上下文
3. **方面**（行为层）定义产生什么配置——每个方面包含所有类的模块
4. **怪癖**（数据流层）定义方面之间如何共享结构化数据——防火墙端口、备份路径等
5. **电池**（预置层）提供开箱即用的可复用方面
6. 管道将所有输入解析为 NixOS/Darwin/Home Manager 的可部署配置

这个概念模型使得 Den 能做到传统方法无法做到的事情：
- **一个方面定义一个关注点**，所有平台共享
- **添加新主机**只需一行 `includes`
- **自定义类**可以扩展到任何 Nix 模块系统
- **上下文驱动**——函数参数形状决定何时激活，无需条件判断
- **代数效应管道**——策略是可组合的、可扩展的一阶值
- **零锁定**——可与任何模块系统集成，支持/不支持 Flakes 均可
