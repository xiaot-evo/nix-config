# 实用模式汇总

本文档从 Den 的 13 个模板中提炼出在实战中最常用的模式。每个模式包含：适用场景、核心代码、以及展示该模式的模板。

______________________________________________________________________

## 1. 两种入口模式

Den 的模板使用两种 flake 入口，区别在于是否需要 flake-parts 的 `perSystem` 支持。

### flake-parts 模式（推荐）

适用于需要完整 perSystem 输出（NixOS、HM、达尔文、包等）的项目。

```nix
outputs = inputs: inputs.flake-parts.lib.mkFlake { inherit inputs; } (inputs.import-tree ./modules);
```

**示例模板**：default、example、diagram-demo、fleet-demo、flake-parts-modules、terranix-demo

### evalModules 模式

适用于追求最简依赖、不需要 perSystem 的场景。

```nix
outputs = inputs:
  (inputs.nixpkgs.lib.evalModules {
    modules = [ (inputs.import-tree ./modules) ];
    specialArgs = { inherit inputs; };
  }).config.flake;
```

**示例模板**：minimal、noflake、ci、microvm、nvf-standalone、scoped-import-tree

## 2. includes / provides 跨类路由

**场景**：主机向用户提供默认包、用户向主机提供配置扩展。

### 主机→用户

```nix
den.aspects.igloo = {
  nixos = { pkgs, ... }: {
    environment.systemPackages = [ pkgs.hello ];
  };
  provides.to-users.homeManager = { pkgs, ... }: {
    home.packages = [ pkgs.vim ];
  };
};
```

`provides.to-users.homeManager` 中的内容会自动合并到用户 `tux` 的 home-manager 配置中。

### 用户→主机

```nix
den.aspects.tux = {
  homeManager = { ... };
  provides.to-hosts.nixos = {
    services.nh.enable = true;
  };
};
```

用户可以通过 `provides.to-hosts` 向主机 NixOS 配置注入内容。

**示例模板**：default、example

## 3. 角色组合模式

**场景**：用分层 include 构建可复用的角色（workstation、server），避免在每个主机方面中重复粘贴。

```nix
# roles/workstation.nix
den.aspects.workstation = {
  includes = [
    den.aspects.networking
    den.aspects.tailscale
    den.aspects.desktop
  ];
};

# hosts/laptop.nix
den.aspects.laptop = {
  includes = [ den.aspects.workstation ];
};

# hosts/devbox.nix — 双角色
den.aspects.devbox = {
  includes = [
    den.aspects.workstation
    den.aspects.server
  ];
};
```

**约束叠加**（diagram-demo 示例）：

```nix
meta.handleWith = [
  (exclude den.aspects.tailscale)         # 排除
  (substitute regreet gdm)               # 替换（greeter 切换）
  (filterBy (a: !isMonitoring a))         # 前缀过滤
];
```

**示例模板**：diagram-demo（3 主机、19+ 方面、角色组合 + 约束）

## 4. 参数化方面

**场景**：方面需要根据实体上下文（host、user）产生不同输出。

### 简单参数化

```nix
den.aspects.mail = { host, ... }: {
  name = "mail/${host.name}";
  nixos.services.postfix = {
    enable = true;
    hostname = host.hostName;
  };
};
```

`{ host, ... }` 作为函数的参数签名，Den 管道在主机作用域内解析时自动注入 host 上下文，确保每台主机产生唯一的方面身份（`mail/laptop`、`mail/server`），防止去重。

### 参数化 + 子方面

```nix
den.aspects.ssh-keys = {
  includes = [
    ({ host, user }: {
      name = "ssh-keys/${user.userName}@${host.name}";
      nixos.users.users.${user.userName}.openssh.authorizedKeys.keys = user.ssh-keys;
    })
  ];
};
```

**示例模板**：example（cooper、setHost）、diagram-demo（mail、backup）、fleet-demo（ssh-keys）

## 5. 子提供者模式

**场景**：一个功能模块包含多个可独立开关的子功能。

```nix
den.aspects.monitoring = {
  nixos.services.prometheus.enable = true;              # 基础功能
  provides.node-exporter.nixos... = ...;                 # 可选子功能
  provides.nginx-exporter.nixos... = ...;                 # 可选子功能
  provides.alerting.nixos... = ...;                       # 可选子功能
};
```

使用方可以选择包含哪些子提供者：

```nix
# 服务器包含全部
den.aspects.server.includes = [ den.aspects.monitoring ];

# 开发机器只选基本
den.aspects.devbox.includes = [ den.aspects.monitoring ] ++ [
  { provides.node-exporter.nixos... = ...; }
];
```

**示例模板**：diagram-demo（monitoring、virtualization）

## 6. Policy 链（Scope 链）

**场景**：需要自定义实体间的解析层级，替代默认的扁平迭代。

### 基本链

```
flake → fleet → environment → host → user
```

### 实现方式

```nix
den.policies.to-fleet = {
  fire = flake: [ (resolve.to "fleet") ];
};

den.policies.fleet-to-envs = {
  fire = fleet: map (name: resolve.to "environment" name) (builtins.attrNames fleet.environments);
};

den.policies.env-to-hosts = {
  fire = { host, ... }: [
    (resolve.to "host" host.name)
  ];
};

den.schema.flake-system.includes = [ den.policies.to-fleet ];
den.schema.fleet.includes = [ den.policies.fleet-to-envs ];
den.schema.environment.includes = [ den.policies.env-to-hosts ];
```

### MicroVM 三层链

```nix
# host → microvm-host → microvm-guest
den.policies.host-to-microvm-host
den.policies.microvm-host-to-microvm-guest
den.policies.microvm-guest-resolve-vm
```

**关键**：禁用默认策略以避免干扰：

```nix
den.schema.flake-system.excludes = [
  den.policies.system-to-os-outputs
  den.policies.system-to-hm-outputs
];
```

**示例模板**：fleet-demo（5 层环境链）、microvm（3 层 VM 链）

## 7. Pipe（Quirk）跨主机数据流

**场景**：同一环境内的兄弟主机共享数据（如负载均衡器收集后端地址）。

### 声明 Pipe

```nix
den.quirks.http-backends = { description = "HTTP 后端地址"; };
```

### 发出数据（Web 服务器）

方面键名匹配 quirk 名，自动触发：

```nix
den.aspects.web-prod-1.http-backends = [
  { addr = "10.0.1.10"; port = 80; }
];
```

### 收集数据（策略）

```nix
den.policies.collect-backends = { host, ... }: [
  (pipe.from "http-backends" [
    (pipe.collect ({ host, ... }: true))  # 收集同环境所有
  ])
];
```

### 消费数据（负载均衡器）

```nix
den.aspects.lb-prod = { http-backends, ... }: {
  nixos.services.haproxy = {
    enable = true;
    backends = builtins.map (b: "${b.addr}:${toString b.port}") http-backends;
  };
};
```

数据范围自动按当前 scope 层级隔离——`prod` 环境的 web 服务器只会被 `prod` 的 lb 收集，与 `staging` 隔离。

**示例模板**：fleet-demo（http-backends + host-addrs）

## 8. 自定义实体类型

**场景**：Den 内置的 host/user/home 不够用，需要新的实体种类（如 environment）。

```nix
# 1. 注册为新实体
den.schema.environment.isEntity = true;

# 2. 创建类型选项
options.fleet.environments = lib.mkOption {
  type = lib.types.attrsOf (lib.types.submodule {
    options.domain-name = lib.mkOption { type = lib.types.str; };
  });
};

# 3. 声明实例
fleet.environments = {
  prod = { domain-name = "example.com"; };
  staging = { domain-name = "staging.example.com"; };
};

# 4. 扩展主机 schema
den.schema.host.imports = [ {
  options.environment = lib.mkOption { type = lib.types.str; };
} ];
```

**示例模板**：fleet-demo（environment 类型 + 注册表驱动用户访问）

## 9. 注册表驱动用户访问

**场景**：用户集中管理，按组授权访问主机，SSH 密钥只落地到有权限的主机。

```nix
# 用户注册表
den.users.registry = {
  alice = { groups = [ "admin" ]; ssh-keys = [ "ssh-ed25519 AAAA..." ]; };
  bob   = { groups = [ "deploy" ]; ssh-keys = [ ... ]; };
};

# 环境授权
fleet.user-access.by-environment = {
  prod    = { groups = [ "admin" ]; };
  staging = { groups = [ "admin" "deploy" ]; };
};
```

策略在每主机作用域检查用户组与环境的交集，只对授权用户创建 scope。SSH 密钥通过参数化子方面在每用户主机上生成独立身份 ID。

**示例模板**：fleet-demo

## 10. 转发类（Forward Class）

**场景**：将 Den 方面的内容路由到第三方 flake-parts 模块（devshell、treefmt、nix-unit 等）。

### 定义转发

```nix
den.lib.policy.route {
  fromClass = "treefmt";            # 方面中写的类键
  intoClass = "flake-parts";        # 目标类
  path = [ "treefmt" ];            # 在 perSystem 中的路径
  adaptArgs = { config, ... }: config.allModuleArgs;
};
```

### 注册类 + 激活策略

```nix
den.classes.treefmt = { };                                         # 注册类
den.schema.flake-parts.includes = [ den.policies.treefmt-to-flake-parts ];  # 激活策略
```

### 用户侧使用

```nix
den.aspects.myProject = {
  treefmt.programs.nixfmt.enable = true;      # → perSystem.treefmt.config.programs.*
  devshell.commands = [ ... ];                # → perSystem.devshells.default.*
  packages = { inherit htop; };               # → perSystem.packages.*
  tests.test-math = { expr = 1 + 1; expected = 2; };  # → perSystem.nix-unit.tests.*
};
```

**示例模板**：flake-parts-modules（5 个转发类）、terranix-demo（terranix 类 + instantiate）、microvm（microvm 类 + 策略链）

## 11. 独立应用（不依赖 NixOS）

**场景**：使用 Den 的方面系统配置纯应用（如 Neovim），不涉及 NixOS/Darwin/HM。

```nix
# 无 den.hosts！直接定义方面
den.aspects.my-neovim = {
  vim.globals.mapleader = " ";
  vim.keymaps = [ ... ];
};

# 手工编译方面为模块
module = den.lib.aspects.resolve "nvf" aspect;

# 馈入外部框架
nvf.lib.neovimConfiguration {
  inherit module;
  pkgs = inputs.nixpkgs.legacyPackages.${system};
};
```

**关键点**：

- 无实体声明（`den.hosts`/`den.homes`）
- 使用 `den.lib.aspects.resolve` 直接编译
- `den.batteries.forward` 自定义类映射（`vim` → `nvf`）

**示例模板**：nvf-standalone、terranix-demo

## 12. 诊断两步式（Capture + Render）

**场景**：可视化方面解析树和提供者关系。

### Step 1：捕捉（Den 框架内）

```nix
fleetCapture = den.lib.capture.captureFleet { };
# 或单主机
captured = den.lib.capture.captureWithPathsWith {
  classes = [ "nixos" "homeManager" ];
  root = den.lib.resolveEntity "host" { inherit host; };
  ctx = { inherit host; };
};
```

### Step 2：投影 + 渲染（den-diagram 库）

```nix
diagram = inputs.den-diagram.lib;
g = diagram.context {
  entries = captured.entries;
  ctxTrace = captured.ctxTrace;
  name = host.name;
};
diagram.toMermaid g   # 或 toPlantUML / toDot / toJSON
```

**示例模板**：diagram-demo（17+ 视图类型）、fleet-demo（fleet 级）

## 13. 作用域库注入（Scoped Import-Tree）

**场景**：减少模块样板代码，自动注入 Den 库和第三方库。

```nix
let
  den-lib = inputs.den.lib { inherit inputs lib config; };
  import-tree =
    inputs.import-tree
      (it: it.addScoped den-lib)
      (it: it.addScoped { inherit ned pipe bend; });
in {
  imports = [ (import-tree ./modules) ];
};
```

注入后，模块中可直接使用：

```nix
{ den, lib, inputs, ned, pipe, bend, ... }:
# den-lib 自动包含 __findFile，<igloo> 语法也有效
```

**示例模板**：scoped-import-tree

## 14. `intoAttr = []` 隐藏实体

**场景**：实体不产生 flake 输出，仅作为路由配置存在于父实体中（如 guest VM）。

```nix
den.hosts.x86_64-linux.guest-microvm = {
  intoAttr = [ ];  # 不产生 flake.nixosConfigurations.*
};

# 在宿主机中引用
den.hosts.x86_64-linux.server.microvm.guests = [
  den.hosts.x86_64-linux.guest-microvm
];
```

guest 的 NixOS 配置在隔离管道中解析，通过 `policy.provide` 注入宿主的 `microvm.vms.<name>`。

**示例模板**：microvm、terranix-demo（每个 host 都通过 instantiate 产生 terranixModules）

## 15. denTest 测试模式

**场景**：编写 Den 框架的单元测试和回归测试。

```nix
{ denTest, ... }:
{
  flake.tests.my-suite = {
    test-my-thing = denTest (
      { den, igloo, tuxHm, ... }:
      {
        den.hosts.x86_64-linux.igloo.users.tux = { };
        den.aspects.igloo.nixos.networking.hostName = "test";
        expr = igloo.networking.hostName;
        expected = "test";
      }
    );
  };
}
```

| denTest 参数 | 值 |
|-------------|-----|
| `den` | den 模块配置 |
| `igloo` | `nixosConfigurations.igloo.config` |
| `tuxHm` | `igloo.home-manager.users.tux` |
| `apple` | `darwinConfigurations.apple.config` |

**运行**：

```bash
just ci                             # 全部
just ci nested-aspects              # 特定套件
just ci nested-aspects.test-direct-nesting-basic  # 特定测试
nix-unit --override-input den . --flake ./templates/ci#.tests.<suite>
```

**示例模板**：ci（133+ 测试用例）、bogus（最小可复现模板）

## 16. npins 锁依赖（无 flake 使用 Den）

**场景**：在无 flakes 的环境中使用 Den，或用 npins 替代 flake.lock。

```nix
let
  sources = import ./npins;
  with-inputs = import sources.with-inputs sources;
  outputs = inputs:
    (inputs.nixpkgs.lib.evalModules {
      modules = [ (inputs.import-tree ./modules) ];
      specialArgs = { inherit inputs; inherit (inputs) self; };
    }).config;
in
with-inputs outputs
```

**构建命令**：

```bash
# nh 风格
nix-run . -A den.sh --run igloo
nix-run . -A den.sh --run 'igloo switch'

# 传统方式
nixos-rebuild build --file . -A flake.nixosConfigurations.igloo
```

**示例模板**：noflake

## 17. 碰撞策略（CollisionPolicy）

**场景**：Den 的上下文参数（`host`、`user` 等）与模块系统的同名参数冲突时控制处理方式。

### 三层解析

| 级别 | 设置位置 | 默认值 |
|------|---------|--------|
| 方面级 | `meta.collisionPolicy` | `null` |
| 实体级 | `den.schema.<kind>.collisionPolicy` | `null` |
| 全局级 | `den.config.classModuleCollisionPolicy` | `"error"` |

### 策略值

| 值 | 行为 |
|----|------|
| `"error"` | 抛出求值错误（有效默认） |
| `"den-wins"` | Den 值优先（发出警告） |
| `"class-wins"` | 模块系统值优先（发出警告） |

**示例模板**：flake-parts-modules（flake-scope 电池使用 `collisionPolicy = "class-wins"`）、10-自定义类.md
