# 常见问题与排错

## 安装和构建问题

### Q: `nix run .#igloo` 失败，说找不到 package

确保 hostname 在 flake.nix 中正确声明：

```nix
den.hosts.x86_64-linux.igloo.aspect = "igloo";
```

Den 从 `den.hosts` 生成 `nixosConfigurations`。如果主机未声明，不会生成 output。

### Q: `nix flake check` 失败

检查 CI 运行的环境：
- CI 设置 `_module.args.CI = true`
- 某些模块可能只在 CI 中有条件激活

尝试本地运行 `nix flake check` 看完整错误信息：

```console
nix flake check 2>&1 | tail -50
```

### Q: 构建时提示 `attribute 'den' missing`

确保 flake.nix 正确使用了 Den：

```nix
{
  outputs = inputs: inputs.den inputs;
}
```

或对于 flake-parts：

```nix
outputs = inputs:
  inputs.flake-parts.lib.mkFlake { inherit inputs; } {
    imports = [ inputs.den.flakeModules.default ];
  };
```

### Q: 提示 `infinite recursion encountered`

常见原因：
1. `den.aspects` 中的方面引用了自身（循环 include）
2. 上下文参数依赖于自身
3. 跨主机 thunk 形成循环依赖图

检查：

```nix
# 避免自我引用
den.aspects.my-aspect = {
  # 不要：includes = [ den.aspects.my-aspect ];
};
```

## 方面不生效

### Q: 方面中的配置没有被应用

可能原因：

**1. 方面未包含**

```nix
# 声明了方面但没包含在任何地方
den.aspects.my-app = {
  nixos.services.my-app.enable = true;
};

# 需要明确的 include
den.aspects.igloo = {
  includes = [ den.aspects.my-app ];
};
```

**2. 上下文参数不匹配**

```nix
# 这个方面只在 host 和 user 都存在时运行
{ host, user }: {
  # 在只有 host 的作用域中不会触发！
};
```

用 `den.lib.policyInspect.inspect` 检查：

```nix
den.lib.policyInspect.inspect {
  kind = "host";
  context = { host = den.hosts.x86_64-linux.igloo; };
}
```

**3. 类名错误**

```nix
# 错误：写成了 nixosXX
den.aspects.igloo = {
  nixos.services.nginx.enable = true;
};

# 正确
den.aspects.igloo = {
  nixos.services.nginx.enable = true;
};
```

**4. 配置在其他类中被覆盖**

```nix
# 后面的 include 可能覆盖前面的
den.aspects.igloo = {
  includes = [
    den.aspects.base
    den.aspects.override
  ];
};
```

### Q: 同一个方面的配置在多个主机之间混乱

方面是纯函数——它们没有全局状态。检查是否在上下文中意外共享了可变数据：

```nix
# 不要：在方面外定义可变数据
let
  ports = [];  # 所有主机共享！
in {
  den.aspects.my-app = { host, ... }: {
    ports = ports ++ [ host.somePort ];
  };
}
```

而应该：

```nix
# 要：方面是纯函数
den.aspects.my-app = { host, ... }: {
  nixos.services.my-app.port = host.somePort;
};
```

## 策略未触发

### Q: 定义了策略但没有生效

**1. 策略未激活**

```nix
# 仅注册
den.policies.my-policy = { host, ... }: [ ... ];

# 还需要激活！
den.schema.host.includes = [ den.policies.my-policy ];
```

**2. 上下文参数不满足**

```nix
# 这个策略需要 user——如果只有 host 在上下文中则不触发
den.policies.my-policy = { host, user, ... }: [ ... ];
```

**3. 被父作用域排除**

```nix
# 父方面排除了该策略
parentAspect = {
  excludes = [ den.policies.my-policy ];
};
```

**4. 策略被自我排除**

策略不会应用于它自己的输出。如果策略 A 创建了新作用域，策略 A 不会在新作用域中再次触发。

### Q: `policy.when` 条件不满足

```nix
den.schema.host.includes = [
  (den.lib.policy.when ({ host, ... }: host.wsl.enable)
    den.policies.wsl-support)
];
```

检查：
- `host.wsl` 是否定义？
- `host.wsl.enable` 是否为 true？

使用 `builtins.trace` 调试：

```nix
(den.lib.policy.when ({ host, ... }:
  builtins.trace host
  host.wsl.enable
) den.policies.wsl-support)
```

### Q: `policy.for` 找不到实体

```nix
den.lib.policy.for den.hosts.x86_64-linux.igloo
  den.policies.my-policy
```

`policy.for` 使用 `id_hash` 进行身份比较。检查实体的 `id_hash`：

```nix
nix-repl> den.hosts.x86_64-linux.igloo.id_hash
"sha256-..."
```

## 作用域相关问题

### Q: 子作用域中的数据没有传播到父作用域

使用 `pipe.expose` 将数据从子作用域暴露到父作用域：

```nix
den.policies.expose-prefs = { host, user, ... }:
  let inherit (den.lib.policy) pipe; in
  [ (pipe.from "prefs" [ pipe.expose ]) ];

den.default.includes = [ den.policies.expose-prefs ];
```

### Q: `pipe.collect` 收集不到数据

```nix
pipe.from "http-backends" [
  (pipe.collect ({ host, ... }: true))
]
```

检查：
1. 兄弟作用域是否在同一父作用域下？（不是父子关系）
2. 谓词是否匹配目标作用域的实体类型？
3. 目标 quirk 是否在兄弟作用域中产生了数据？
4. 目标 quirk 是否已声明在 `den.quirks` 中？

### Q: 作用域 ID 冲突

确保实体有唯一的名称。作用域 ID 从上下文中的 `name` 属性派生：

```nix
# 两个同名的主机会导致作用域冲突
den.hosts.x86_64-linux.igloo.aspect = "igloo";
# ... 另一个系统 ...
den.hosts.aarch64-linux.igloo.aspect = "igloo";  # 同名但不同系统——OK
```

## 类碰撞问题

### Q: 收到 `collisionPolicy` 错误

```nix
error: collision between den arg and module arg: lib
```

解决：

```nix
# 在 schema 级别设置碰撞策略
den.schema.host.collisionPolicy = "class-wins";

# 或对特定值使用 pipelineOnly
den.lib.policy.pipelineOnly someValue;
```

### Q: 自定义类的内容没有到达目标

```nix
den.classes.myapp = {
  description = "我的类";
};

# 使用了自定义类
den.aspects.alice = {
  myapp.setting = true;
};
```

检查：
1. 类是否注册在 `den.classes` 中？
2. 是否有 `forward` 将 `myapp` 转发到目标类？
3. `forward` 中的路径是否正确？

```nix
# 需要一个 forward 将 myapp 转发到 nixos 之类
den.batteries.forward {
  each = lib.singleton user;
  fromClass = _: "myapp";
  intoClass = _: host.class;
  intoPath = _: [ "services" "myapp" ];
  fromAspect = _: den.aspects.${user.aspect};
};
```

### Q: `den.batteries.forward` 的 `guard` 不工作

检查 guard 函数签名：

```nix
# guard 接收模块系统参数，如果有第二个参数则是 item
guard = { options, ... }: options ? wsl;  # 没有 item 参数

# 或带 item 参数的形式：
guard = { options, ... }: _item: lib.mkIf (options ? wsl);
```

- 使用 `lib.optionalAttrs` 测试选项是否定义
- 使用 `lib.mkIf` 测试配置值

## 调试方法汇总

### 1. REPL 检查

```console
$ nix repl
nix-repl> :lf .
nix-repl> nixosConfigurations.igloo.config.networking.hostName
```

### 2. PolicyInspect

```nix
den.lib.policyInspect.inspect {
  kind = "host";
  context = { host = den.hosts.x86_64-linux.laptop; };
}
```

### 3. builtins.trace

```nix
({ host, ... }@ctx: builtins.trace ctx {
  nixos.networking.hostName = host.hostName;
})
```

### 4. builtins.break

```nix
({ host, ... }@ctx: builtins.break ctx {
  nixos = { };
})
```

### 5. diag 可视化

```nix
diag = den.lib.diag;
g = diag.hostContext { host = den.hosts.x86_64-linux.laptop; };
diag.toMermaid g
```

### 6. 手动解析

```console
nix-repl> den.hosts.x86_64-linux.igloo.mainModule
```

### 7. 暴露 den 到 flake 输出

```nix
{ den, ... }: {
  flake.den = den;  # 调试后移除
}
```

```console
nix-repl> :lf .
nix-repl> den.aspects.igloo
nix-repl> den.hosts.x86_64-linux.igloo
nix-repl> den.policies
```
