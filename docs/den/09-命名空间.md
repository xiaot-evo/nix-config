# 命名空间（Namespaces）

## 为什么需要命名空间

随着 Den 配置的增长，方面（aspects）的数量会迅速增加。命名空间解决了两个核心问题：

1. **组织**：将方面分组到逻辑命名空间（如 `common`、`servers`、`workstations`）
1. **共享**：在 flake 之间发布和消费方面库

命名空间创建一个作用域化的方面库，位于 `den.ful.<name>` 下。

## `den.ful`——Den 的命名空间系统

`den.ful` 是 Den 的命名空间容器。它是一个内部的 deferred module，包含多个命名空间条目，每个条目包含自己的方面集合：

```nix
options.den.ful = lib.mkOption {
  description = "Den 命名空间——内部方面树";
  type = lib.types.attrsOf namespaceType;
};
```

命名空间还可以通过 `flake.denful` 导出到 flake 输出，供其他 flake 消费：

```nix
options.flake.denful = lib.mkOption {
  type = lib.types.attrsOf lib.types.raw;
};
```

## 创建命名空间

使用 `inputs.den.namespace` 函数创建命名空间：

```nix
# modules/namespace.nix
{ inputs, den, ... }: {
  # 创建 "my" 命名空间（不导出到 flake 输出）
  imports = [ (inputs.den.namespace "my" false) ];

  # 或创建并导出 "eg" 命名空间
  imports = [ (inputs.den.namespace "eg" true) ];
}
```

这会自动创建：

- `den.ful.eg`——命名空间 attrset（方面类型化）
- `eg`——指向 `den.ful.eg` 的模块参数别名
- `flake.denful.eg`——flake 输出（如果导出）

命名空间选项的定义：

```nix
namespaceType = lib.types.submodule ({ name, ... }: {
  options.schema = lib.mkOption {
    description = "命名空间 schema——每实体类型的自由形式 deferred module";
    type = lib.types.submodule {
      freeformType = lib.types.lazyAttrsOf lib.types.deferredModule;
    };
    default = { };
  };
  options.classes = lib.mkOption {
    description = "导入时合并到 den.classes 的类声明";
    type = lib.types.lazyAttrsOf lib.types.raw;
    default = { };
  };
});
```

命名空间支持：

- **`schema`**：为命名空间声明自定义实体类型的 schema
- **`classes`**：命名空间级别的类声明，导入时合并到 `den.classes`

## 填充命名空间

在任何模块中定义命名空间下的方面：

```nix
# modules/aspects/vim.nix
{ eg, ... }: {
  eg.vim = {
    homeManager.programs.vim.enable = true;
  };
}

# modules/aspects/desktop.nix
{ eg, ... }: {
  eg.desktop = {
    includes = [ eg.vim ];
    nixos.services.xserver.enable = true;
  };
}
```

命名空间可以包含无限嵌套的方面结构：

```nix
{ eg, ... }: {
  eg.servers.web = {
    nixos.services.nginx.enable = true;
  };
  eg.servers.db = {
    nixos.services.postgresql.enable = true;
  };
}
```

## 导出命名空间

导出的命名空间出现在 `flake.denful.<name>` 中，供其他 flake 导入：

```nix
{ inputs, ... }: {
  imports = [ (inputs.den.namespace "shared" true) ];
}

# 在其他 flake 中：
# flake.denful.shared 包含所有方面
```

对于已导出的命名空间，`flake.denful.<name>` 自动添加到 flake 输出。

## 导入外部命名空间

从上游 flake 合并命名空间：

```nix
# modules/namespace.nix
{ inputs, ... }: {
  # 从上游导入 "shared" 命名空间，与本地定义合并
  imports = [ (inputs.den.namespace "shared" [ inputs.team-config ]) ];
}
```

`namespace` 函数接受第二个参数，可以是：

- **布尔值**（`true`/`false`）——`true` 表示导出到 flake 输出，`false` 表示仅本地
- **来源列表**——从上游 flake 合并的来源列表。可以在列表中包含 `true` 以同时导出合并结果，如 `[ inputs.team-config true ]`

每个来源的 `flake.denful.<name>` 合并到 `den.ful.<name>`：

```nix
# namespace.nix 的实现
name: sources: { config, lib, ... }:
let
  from = lib.flatten [ sources ];
  isOutput = builtins.elem true from;
  denfuls = map (lib.getAttrFromPath [ "denful" name ])
    (builtins.filter builtins.isAttrs from);

  # 剥离 _ 别名以避免重复
  stripAliases = lib.mapAttrs (_: v:
    if builtins.isAttrs v then
      builtins.removeAttrs v [ "_" "__functor" ]
    else v
  );

  sourceModules = map (denful: {
    config.den.ful.${name} = stripAliases denful;
  }) denfuls;

  # 创建别名模块参数
  aliasModule = lib.mkAliasOptionModule [ name ] [ "den" "ful" name ];

  # 如果导出，添加到 flake 输出
  outputModule = lib.optionalAttrs isOutput {
    config.flake.denful.${name} = config.den.ful.${name};
  };

  # 合并外部类的声明
  traitClassModule = {
    config.den.classes = lib.mkMerge (map (denful: denful.classes or { }) denfuls);
  };
in {
  imports = sourceModules ++ [ aliasModule outputModule traitClassModule ];
  config._module.args.${name} = config.den.ful.${name};
}
```

### 类合并机制

当导入外部命名空间时，其中的类声明（`.classes`）自动合并到 `den.classes`。这确保自定义类的正确注册和路由。

## 使用命名空间的方面

引用命名空间方面有两种方式：

### 通过模块参数

```nix
{ eg, ... }: {
  den.aspects.laptop.includes = [
    eg.desktop
    eg.vim
  ];
}
```

### 通过角度括号语法

```nix
{ den, ... }: {
  _module.args.__findFile = den.lib.__findFile;

  den.aspects.laptop.includes = [
    <eg/desktop>
    <eg/vim>
  ];
}
```

## 命名空间解析规则

当使用角度括号语法 `<den/path>` 或 `<namespace/path>` 时，解析规则如下：

1. **`<den/...>`**——当路径以 `den/` 开头：

   - 检查 `den.batteries` 提供者
   - 否则从 `config.den` 按路径解析

1. **`<aspect-name/...>`**——当顶级键匹配方面：

   - 解析到 `den.aspects.<aspect-name>`
   - 深层路径通过 `provides` 机制解析

1. **`<namespace/...>`**——当顶级键在 `den.ful` 中：

   - 解析到命名空间方面
   - 深层路径通过方面提供链解析

```nix
# <den/batteries/hostname> → config.den.batteries.hostname
# <igloo>                  → den.aspects.igloo
# <eg/desktop>             → den.ful.eg.desktop
```

## `<den/batteries/hostname>` 角度括号语法

角度括号语法通过 `den.lib.__findFile` 实现：

```nix
# 启用角度括号语法
{ den, ... }:
{
  _module.args.__findFile = den.lib.__findFile;
}
```

`__findFile` 的工作方式（来自 `den-brackets.nix`）：

1. 将路径路径（如 `"den/batteries/hostname"`）拆分为路径段
1. 如果以 `den/` 开头，检查 `den.batteries` 提供者，否则从 `config.den` 解析
1. 如果匹配方面名称，从 `den.aspects` 解析
1. 如果匹配命名空间，从 `den.ful` 解析
1. 深层路径通过 `provides` 或直接嵌套键解析

## 内部使用 `__findFile` 的实现机制

`__findFile` 的核心实现机制：

```nix
# 简化后的逻辑
findAspect = path:
  let head = lib.head path; tail = lib.tail path; in
  if head == "den" then
    # 处理 <den/...>
    # 检查是否在 batteries 中
    ...
  else if builtins.hasAttr head config.den.aspects then
    # 处理 <aspect-name/...>
    ...
  else if lib.hasAttrByPath [ "ful" head ] config.den then
    # 处理 <namespace/...>
    ...
  else
    throw "未找到方面：${lib.concatStringsSep "." path}";
```

### 为什么需要 `__findFile`

Nix 的角度括号语法（`<path>`）最初用于 Nix 搜索路径。Den 重用了这个语法，通过设置 `__findFile` 来实现自定义的方面引用语法。这允许：

- 更简洁的引用：`<eg/vim>` 比 `den.ful.eg.vim` 更短
- 深层路径访问：`<eg/servers/web>` 自动解析嵌套方面
- 命名空间隔离：不同命名空间的同名方面不会冲突

## 完整示例

### 创建、填充、导入命名空间

```nix
# === 项目 A：定义并导出命名空间 ===

# modules/namespace.nix
{ inputs, ... }: {
  imports = [
    # 创建 "common" 命名空间并导出
    (inputs.den.namespace "common" true)
    # 创建 "servers" 命名空间（不导出）
    (inputs.den.namespace "servers" false)
  ];
}

# modules/common/vim.nix
{ common, ... }: {
  common.vim = {
    homeManager.programs.vim = {
      enable = true;
      extraConfig = "set number";
    };
  };
};

# modules/common/git.nix
{ common, ... }: {
  common.git = {
    homeManager.programs.git = {
      enable = true;
      userName = "Default User";
      userEmail = "user@example.com";
    };
  };
};

# modules/common/desktop.nix
{ common, ... }: {
  common.desktop = {
    includes = [ common.vim ];
    nixos.services.xserver.enable = true;
    homeManager = { ... }: {
      programs.firefox.enable = true;
    };
  };
};

# modules/servers/web.nix
{ servers, ... }: {
  servers.web = {
    nixos.services.nginx.enable = true;
    firewall = { ports = [ 80 443 ]; };
  };
};

# modules/servers/db.nix
{ servers, ... }: {
  servers.db = {
    nixos.services.postgresql.enable = true;
    firewall = { ports = [ 5432 ]; };
  };
};

# === 项目 B：导入并使用命名空间 ===

# flake.nix
{
  inputs = {
    den.url = "github:denful/den";
    project-a.url = "github:user/project-a";
  };
}

# modules/import-ns.nix
{ inputs, den, ... }: {
  # 从 project-a 导入 common 命名空间
  imports = [ (inputs.den.namespace "common" [ inputs.project-a ]) ];

  # 注入到所有主机
  den.default.includes = [
    # 使用命名空间方面
    ({ common, ... }: { includes = [ common.desktop ]; })
  ];
}

# modules/hosts/my-server.nix
{ common, servers, ... }: {
  den.aspects.my-server = {
    includes = [
      common.desktop
      servers.web
      servers.db
    ];
  };
}
```

这个示例展示了命名空间的完整生命周期：定义、填充、导出、导入、使用。
