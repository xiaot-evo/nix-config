# Den 框架简介

## 什么是 Den？

Den（全称 `denful/den`）是一个 **面向方面（Aspect-Oriented）的树状分支（Dendritic）Nix 配置框架**。它的核心理念是：**以功能为中心，而不是以主机为中心**。

Den 不是又一个 Nix 模块系统——它是一个**数据转换管道**，接收你的基础设施实体（主机、用户、家庭环境）声明，应用一系列**方面（aspects）** 函数，最终产生 NixOS、Darwin、Home Manager 或其他 Nix 模块系统的配置。

> Den 的名称来源于 "Dendritic"（树状分支）——配置像树枝一样从主干分叉，每个方面（feature）覆盖多个平台，而不是每个平台重复书写相同的配置。

### 核心思想：一行代码实现跨平台功能

传统方式下，在三台机器上启用蓝牙意味着三个文件中的重复配置：

```nix
# 没有 Den —— 跨主机和模块系统复制粘贴
hosts/laptop/configuration.nix   # hardware.bluetooth.enable = true
hosts/laptop/home.nix            # services.blueman-applet.enable = true
hosts/desktop/configuration.nix  # hardware.bluetooth.enable = true（又一遍）
hosts/mac/darwin.nix             # homebrew.casks = [ "blueutil" ]（不同语法）
```

使用 Den，一个方面搞定所有平台：

```nix
# 有了 Den —— 一个方面配置所有平台
den.aspects.bluetooth = {
  nixos.hardware.bluetooth.enable = true;
  homeManager.services.blueman-applet.enable = true;
  darwin.homebrew.casks = [ "blueutil" ];
};

# 每个包含它的主机自动获得蓝牙——跨所有类
den.aspects.laptop.includes = [ den.aspects.bluetooth ];
den.aspects.desktop.includes = [ den.aspects.bluetooth ];
```

## Den 与传统 NixOS 配置的区别

### 传统方式：面向主机（Host-First）

在传统的 NixOS 配置中，组织单位是**主机**。每个主机有自己的 `configuration.nix`，混入各种模块，用户配置通常分散在多个文件中。

```
flake.nix
├── hosts/
│   ├── laptop/    # 蓝牙、开发工具、桌面环境
│   ├── desktop/   # 蓝牙、开发工具、NVIDIA 驱动
│   └── server/    # 没有蓝牙，但有 Web 服务
```

如果你想在所有机器上添加一个开发工具，你需要在每个主机配置文件中添加。如果你想移除，需要在每个文件中删除。

### Den 方式：面向方面（Aspect-First）

Den 将组织单位从"主机"翻转为**方面（aspect）**——每个方面是一个独立的**关注点**，包含它在所有平台上的配置：

```
flake.nix
├── aspects/
│   ├── bluetooth.nix    # 一个方面 = 所有平台
│   ├── dev-tools.nix    # 一个方面 = 所有平台
│   └── desktop.nix      # 主机方面的组合
```

添加功能 = 添加一个方面。移除功能 = 删除一行 `includes`。

## 核心哲学

### 零依赖（Zero-Dependency）

Den 的核心库（`den.lib`）没有任何外部依赖——它只使用纯 Nix 语言特性（`__functor`、`builtins.functionArgs` 等）。你可以将它用于任何 Nix 模块系统，无需 NixOS、Darwin 或 Home Manager。

### 一切都是可选的（Everything is Optional）

- 不支持 Flakes？——可以用 `npins` 和 `default.nix`
- 只用 NixOS 不用 Darwin？——可以，Darwin 方面的配置不会生成
- 不用 Home Manager？——不用加 `homeManager` 类
- 想用自己的模块系统？——只用 `den.lib`，不要框架

### 代数效应管道（Algebraic Effects Pipeline）

Den 的配置解析并非简单的"合并模块"，而是基于\*\*代数效应（algebraic effects）\*\*的管道。方面编译为计算（computations），处理器（handlers）决定解决策略。这使得策略（policies）可以驱动实体拓扑、路由内容，并可无限扩展。

### 面向方面（Aspect-Oriented）

如果你熟悉面向方面编程（AOP），你会发现 Den 使用了类似的切入（pointcut）模式：策略（policies）定义了在管道的哪些点上应用哪些方面的配置。

## Den 的两种使用方式

### 作为库（独立 lib）

`den.lib` 是领域无关的。它只提供 parametric dispatch、aspect resolution 等核心原语，不假设你使用 NixOS、Darwin 或任何特定模块系统。

```nix
# 为自定义领域定义方面
den.aspects.web-server = {
  terranix.resource.aws_instance.web = { ami = "..."; };
};

# 手动解析
aspect = den.lib.aspects.resolve "terranix" [] den.aspects.web-server;
```

适用于：Terranix、NixVim、system-manager 或任何自定义 Nix 模块系统。

### 作为框架（完整 flake 模块）

Den 框架在 `den.lib` 之上提供了完整的 NixOS/Darwin/Home Manager 集成：

- **Schema 类型**（`den.hosts`、`den.homes`）——声明主机和用户
- **方面和策略**（`den.aspects`、`den.policies`）——解析管道
- **电池**（`den.batteries.*`）——常用 OS 配置模式
- **输出生成**——自动产生 `nixosConfigurations`、`darwinConfigurations` 等

## 适用场景

| 场景 | 说明 |
|------|------|
| **单主机** | 简单场景也没问题。Den 不会因为简单而变得复杂 |
| **多主机集群** | 方面在不同主机间复用，无需复制粘贴 |
| **跨平台（NixOS + Darwin）** | 一个方面同时配置 Linux 和 macOS |
| **家庭管理器管理** | 支持 home-manager、hjem、nix-maid 三种家庭环境 |
| **多用户管理** | 主机与用户的双向配置共享 |
| **团队/社区共享** | 命名空间（namespaces）支持发布和消费外部方面库 |

## Den 生态

- **Den 框架**（`denful/den`）——核心框架
- **denful**（`denful/denful`）——第三方方面分发平台（类似 lazyvim 的配置分发）
- **den 库**（`den.lib`）——独立于框架的核心库
- **dendrix**——方面索引和生态系统探索
- **flake-aspects**——Den 的前身，独立的方面库
- **import-tree**——递归模块导入工具

## 与其他框架的对比

| 特性 | Den | flake-parts | snowfall | blueprint |
|------|-----|-------------|----------|-----------|
| 面向方面 | **原生** | 无 | 文件系统约定 | 无 |
| 跨平台方面 | **原生** | 手动 | 手动 | 手动 |
| 代数效应管道 | **有** | 无 | 无 | 无 |
| 参数化分发 | **自动** | 手动 | 文件系统 | 手动 |
| 自定义类 | **支持** | 无 | 无 | 无 |
| 命名空间 | **支持** | 无 | 无 | 无 |
| 非 Flake 支持 | **完整** | 不支持 | 不支持 | 不支持 |
| 管道/怪癖 | **有** | 无 | 无 | 无 |

### 传统写法 vs Den 写法

**传统 NixOS 方式：**

```nix
# configuration.nix
{ config, pkgs, ... }: {
  networking.hostName = "my-laptop";
  networking.firewall.enable = true;
  services.openssh.enable = true;
  users.users.alice = {
    isNormalUser = true;
    extraGroups = [ "wheel" ];
  };
  home-manager.users.alice = { pkgs, ... }: {
    home.packages = [ pkgs.htop pkgs.git ];
    programs.zsh.enable = true;
  };
}
```

**Den 方式——关注点分离：**

```nix
# 模块 1：主机声明
{ ... }: {
  den.hosts.x86_64-linux.my-laptop.users.alice = {};
}

# 模块 2：主机方面
{ ... }: {
  den.aspects.my-laptop = {
    includes = [
      den.batteries.hostname
      { nixos.networking.firewall.enable = true; }
      { nixos.services.openssh.enable = true; }
    ];
  };
}

# 模块 3：用户方面
{ ... }: {
  den.aspects.alice = {
    includes = [
      den.batteries.define-user
      den.batteries.primary-user
    ];
    homeManager = { pkgs, ... }: {
      home.packages = [ pkgs.htop pkgs.git ];
      programs.zsh.enable = true;
    };
  };
}
```

### 跨平台示例

假设你有一台 NixOS 笔记本和一台 macOS 工作站，都需要相同的开发工具：

```nix
# 一个方面 = 所有平台
den.aspects.dev-tools = {
  nixos.environment.systemPackages = [ pkgs.ripgrep pkgs.fd ];
  darwin.environment.systemPackages = [ pkgs.ripgrep pkgs.fd ];
  homeManager.home.packages = [ pkgs.ripgrep pkgs.fd ];
};

# 应用到所有主机
den.default.includes = [ den.aspects.dev-tools ];
```

添加新工具？改一个地方。所有主机、所有平台自动更新。
