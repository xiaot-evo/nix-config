# 方面配置指南

**方面（Aspect）** 是 Den 框架的核心配置单元。每个方面是一个函数或属性集，包含属于特定实体的 NixOS、nix-darwin、home-manager 等配置。

## 方面的基本结构

最简单的方面是包含类键的属性集：

```nix
{
  den.aspects.my-host = {
    nixos = {
      networking.hostName = "myhost";
      services.openssh.enable = true;
    };
  };
}
```

对于需要上下文感知的配置，方面可以是一个函数：

```nix
{
  den.aspects.my-host = { host, ... }: {
    nixos = {
      networking.hostName = host.hostName;
      system.stateVersion = "25.05";
    };
  };
}
```

## 上下文参数

方面函数接收丰富的上下文参数，用于感知其运行的实体环境：

```nix
{
  den.aspects.configured = { host, user, home, config, lib, inputs, ... }: {
    nixos = {
      # host 提供主机选项
      networking.hostName = host.hostName;

      # 访问 flake inputs
      environment.systemPackages = [ inputs.nixpkgs.legacyPackages.${host.system}.hello ];
    };

    homeManager = {
      # user 提供用户选项
      home.username = user.userName;

      # home 在独立 HM 中可用
      home.homeDirectory = home.homeDirectory;
    };
  };
}
```

关键上下文参数：

| 参数 | 可用场景 | 说明 |
|------|---------|------|
| `host` | 所有 | 当前主机实体 |
| `user` | 用户作用域 | 当前用户实体 |
| `home` | 独立 HM | 当前家庭实体 |
| `config` | 所有 | 当前模块的 config |
| `lib` | 所有 | nixpkgs lib |
| `inputs` | 所有 | flake inputs |
| `class` | 参数化 | 当前解析的类 |
| `system` | 主机 | 平台字符串 |

## Owned Configs（自有配置）

方面中的顶级键如果匹配已注册的类，则属于该类的"自有配置"。Den 默认注册的类：

- `nixos` — NixOS 系统配置
- `darwin` — nix-darwin 配置
- `homeManager` — Home Manager 用户配置
- `user` — OS 级用户配置（需电池支持）
- `os` — 同时路由到 nixos 和 darwin 的便捷类

```nix
{
  den.aspects.workstation = {
    # 自有配置：NixOS
    nixos = {
      boot.loader.systemd-boot.enable = true;
      networking.firewall.enable = true;
    };

    # 自有配置：Home Manager
    homeManager = { pkgs, ... }: {
      home.packages = [ pkgs.neovim ];
    };

    # 自有配置：OS（同时路由到 nixos 和 darwin）
    os = {
      time.timeZone = "Asia/Shanghai";
    };
  };
}
```

## Includes：引入其他方面

`includes` 列表是方面组合的核心机制，支持三种形式：

### 1. 静态属性集

```nix
{
  den.aspects.full = {
    includes = [
      {
        nixos.services.openssh.enable = true;
      }
    ];
  };
}
```

### 2. 静态方面叶（电池或已定义方面）

```nix
{
  den.aspects.my-user = {
    includes = [
      den.batteries.define-user
      den.batteries.primary-user
      (den.batteries.user-shell "fish")
    ];

    homeManager = { pkgs, ... }: {
      home.packages = [ pkgs.htop ];
    };
  };
}
```

### 3. 参数化（上下文感知函数）

```nix
{
  den.aspects.auto-configured = {
    includes = [
      ({ host, ... }: {
        nixos.networking.hostName = host.hostName;
      })
    ];
  };
}
```

## Provides / `_`：子方面命名空间

`provides`（别名 `_`）是方面的子命名空间，用于组织可选的子方面，方便按需包含：

```nix
{
  den.aspects.server = {
    nixos.services.nginx.enable = true;

    provides = {
      # 可选的监控子方面
      monitoring.nixos = {
        services.prometheus.enable = true;
        services.grafana.enable = true;
      };

      # 可选的日志子方面
      logging.nixos.services.loki.enable = true;
    };
  };
}

# 按需使用子方面
{
  den.aspects.production-server = {
    includes = [
      den.aspects.server
      den.aspects.server.monitoring  # 只包含监控部分
    ];
  };
}
```

`provides` 也用于跨实体交付。主机可以向用户交付配置：

```nix
{
  den.aspects.igloo = {
    nixos = { ... };

    # 通过 provides.to-users 向该主机的用户交付家庭配置
    provides.to-users.homeManager = { pkgs, ... }: {
      home.packages = [ pkgs.vim ];
    };
  };

  den.aspects.tux = {
    includes = [ den.batteries.host-aspects ];
    # 会自动接收主机 igloo 提供的 homeManager 配置
  };
}
```

反之，用户也可以向主机交付配置：

```nix
{
  den.aspects.tux = {
    provides.to-hosts.nixos = {
      users.users.tux.extraGroups = [ "wheel" ];
    };
  };
}
```

`_` 是 `provides` 的别名，两者可互换：

```nix
{
  den.aspects.app = {
    _.web.nixos.services.nginx.enable = true;
    _.db.nixos.services.postgresql.enable = true;
  };

  # 等价于：
  # provides.web.nixos...
  # provides.db.nixos...
}
```

## Den.Default：默认方面

`den.default` 是一个特殊的方面，会自动注入到**所有**实体（主机、用户、家庭）中，适合放置全局配置：

```nix
{
  # 全局设置
  den.default = {
    nixos.system.stateVersion = "25.05";
    homeManager.home.stateVersion = "25.05";
  };

  # 全局电池
  den.default.includes = [
    den.batteries.hostname
    den.batteries.unfree
  ];

  # 全局严格模式
  den.schema.host = den.lib.strict;
}
```

`den.lib.strict` 结合 `den.default` 可以强制所有主机遵循统一规范。

## Meta 字段

每个方面可以携带元数据，用于文档和条件逻辑：

```nix
{
  den.aspects.desktop = {
    meta = {
      description = "桌面环境配置";
      tags = [ "desktop" "gui" "graphical" ];
      categories = [ "environment" ];
    };

    nixos = { ... };
  };
}
```

## 方面的四种形态

Den 的 FX 管线根据方面的结构特征，将其分为四种形态：

### 1. 静态方面

最基础的形态——属性集中不包含特殊字段：

```nix
{
  den.aspects.basic = {
    name = "basic";
    nixos.services.openssh.enable = true;
  };
}
```

### 2. 参数化方面（`__args` + `__fn`）

当方面中包含 `__fn` 和 `__args` 时，它是一个参数化方面，管线会按照 `__args` 中声明的要求解析上下文，然后将解析后的参数传递给 `__fn`：

```nix
{
  den.aspects.conditional-packages = {
    __functor = _self: packages: {
      name = "packages(${builtins.concatStringsSep "," packages})";
      __fn = { class, host ? null, ... }: {
        ${class}.environment.systemPackages = map (p: pkgs.${p}) packages;
      };
      __args = { class = true; host = true; };
    };
  };
}

# 使用
{
  den.aspects.my-host.includes = [
    (den.aspects.conditional-packages [ "htop" "vim" ])
  ];
}
```

`den.batteries.unfree` 和 `den.batteries.insecure` 是参数化方面的典型实现。

### 3. 转发方面（`meta.__forward`）

当一个类的内容需要路由到另一个类的选项路径时，使用转发方面。`meta.__forward` 包含转发规格：

```nix
{
  # 手动实现 homeManager 类转发
  den.aspects.hm-forward = {
    meta.__forward = {
      fromClass = "homeManager";
      intoClass = "nixos";
      staticIntoPath = [ "home-manager" "users" "tux" ];
      sourceAspect = { };  # 源方面，此处使用空表示当前方面自身
    };
  };
}
```

更便捷的做法是使用 `den.batteries.forward` 电池：

```nix
{
  den.aspects.custom-env = den.batteries.forward {
    each = lib.singleton true;
    fromClass = _: "custom";
    intoClass = _: "nixos";
    intoPath = _: [ "services" "my-service" ];
    fromAspect = _: den.lib.resolveEntity "user" { host = host; user = user; };
  };
}
```

### 4. 条件方面（`meta.guard`）

条件方面根据 `meta.guard` 函数的返回值决定是否启用：

```nix
{
  den.aspects.vm-config = {
    meta = {
      # 只有当主机有 virtualisation 方面时才启用
      guard = ctx: ctx.hasAspect { name = "virtualisation"; };
      aspects = [
        {
          nixos = {
            services.qemu.guest-agent.enable = true;
            virtualisation.vmVariant = {
              virtualisation.memorySize = 2048;
            };
          };
        }
      ];
    };
  };
}
```

`guard` 函数接收一个包含 `hasAspect` 方法的上下文对象，可以查询某方面是否在体系中出现。当 guard 返回 `false` 时，管线会创建"墓碑"（tombstone）跳过该方面。

## Fixed-Point（Self 引用）

方面可以通过 `meta.self` 引用自身，实现自指配置：

```nix
{
  den.aspects.self-aware = { config, ... }: {
    meta.self = config;
    nixos.services.nginx.virtualHosts."example.com" = {
      forceSSL = config.meta.self.nixos.services.nginx.enable;
    };
  };
}
```

## Mutal Provider：双向配置

主机的方面可以影响用户，用户的方面也可以影响主机，实现 Host↔User 双向配置：

```nix
{
  # 主机向特定用户交付配置
  den.aspects.igloo = {
    policies.to-tux = { host, user, ... }:
      lib.optional (user.name == "tux") (
        den.lib.policy.include {
          homeManager.home.shellAliases.g = "git";
        }
      );
    includes = [ den.aspects.igloo.policies.to-tux ];
  };

  # 用户向主机交付配置
  den.aspects.tux = {
    policies.to-igloo = { host, user, ... }:
      lib.optional (host.name == "igloo") (
        den.lib.policy.include {
          nixos.boot.kernel.randstructSeed = "custom-seed";
        }
      );
    includes = [ den.aspects.tux.policies.to-igloo ];
  };
}
```

## 完整示例

以下是从简单到复杂的一系列示例：

### 简单：静态主机配置

```nix
{
  den.aspects.server = {
    nixos = {
      networking.firewall.enable = true;
      services.nginx.enable = true;
    };
  };
}
```

### 中级：使用电池的用户配置

```nix
{
  den.aspects.alice = {
    includes = [
      den.batteries.define-user
      den.batteries.primary-user
      (den.batteries.user-shell "zsh")
    ];

    nixos.users.users.alice.extraGroups = [ "docker" ];
    homeManager = { pkgs, ... }: {
      home.packages = [ pkgs.neovim pkgs.git ];
    };
  };
}
```

### 高级：复杂的多层方面

```nix
{ lib, den, ... }: {
  den.aspects.workstation = {
    meta = {
      description = "完整工作站配置";
      tags = [ "desktop" "development" ];
    };

    includes = [
      # 基础电池
      den.batteries.hostname
      den.batteries.unfree

      # 主机级子方面
      den.aspects.workstation.hardware
      den.aspects.workstation.network
    ];

    # 自有配置
    nixos = { pkgs, ... }: {
      environment.systemPackages = with pkgs; [ git vim ];
    };

    homeManager = { pkgs, ... }: {
      home.packages = with pkgs; [ ripgrep fd ];
    };

    # 条件子方面
    provides.gpu-nvidia = {
      meta.guard = ctx: ctx.hasAspect { name = "nvidia"; };
      nixos.hardware.nvidia.prime = {
        intelBusId = "PCI:0:2:0";
        nvidiaBusId = "PCI:1:0:0";
      };
    };

    # 参数化子方面
    provides.packages = {
      __functor = _self: pkgs: {
        name = "extra-pkgs";
        __fn = { class, ... }: {
          ${class}.environment.systemPackages = pkgs;
        };
        __args = { class = true; };
      };
    };

    # 子方面命名空间
    _ = {
      monitoring.nixos = {
        services.prometheus.enable = true;
      };
      logging.nixos.services.loki.enable = true;
    };
  };
}
```

## 最佳实践

### 方面拆分粒度

- **按功能拆分**：每个方面负责一个独立功能（网络、监控、桌面）
- **按实体拆分**：主机方面、用户方面分离
- **可组合性**：通过 `includes` 组合小方面构建大配置

### 复用模式

- 使用 `den.default` 放置全局通用配置
- 使用 `provides.to-users` / `provides.to-hosts` 实现跨实体复用
- 使用 `den.batteries.forward` 创建自定义类转发

### 设计原则

- 优先使用静态方面，必要时才使用参数化
- 条件方面用于"有则启用，无则跳过"的场景
- 命名空间（provides/_）帮助组织大型方面树
- `includes` 是组合的推荐方式，避免直接嵌套
