# 自定义类

## 什么是类（Classes）

**类（Class）** 是 Den 中的输出桶——它决定了配置的去向。每个类对应一个 Nix 模块系统（如 NixOS、Home Manager），方面（aspects）上的类键名告诉 Den：这段配置属于哪个输出域。

```nix
den.aspects.my-server = {
  nixos.services.nginx.enable = true;      # 输出到 NixOS
  homeManager.programs.git.enable = true;  # 输出到 Home Manager
};
```

## 内置类

Den 预定义了以下类：

| 类名 | 描述 | 输出目标 |
|---|---|---|
| `nixos` | NixOS 系统配置 | `nixosConfigurations.<name>` |
| `darwin` | nix-darwin 系统配置 | `darwinConfigurations.<name>` |
| `homeManager` | Home Manager 用户配置 | `homeConfigurations.<name>` |
| `user` | OS 用户配置 | 转发到 `users.users.<name>` |
| `os` | 跨平台 OS 配置 | 同时转发到 nixos 和 darwin |
| `wsl` | WSL 配置 | 转发到 `wsl` 选项 |
| `hjem` | hjem 用户环境 | 转发到 `hjem.users.<name>` |
| `maid` | nix-maid 配置 | 转发到 `users.users.<name>.maid` |

## 注册自定义类

使用 `den.classes.<name>` 注册新类：

```nix
{ den, ... }: {
  den.classes.myapp = {
    description = "我的应用配置类";
  };
}
```

类选项接受 `description`（描述）和可选的 `forwardTo`（转发目标）。

### 通过方面声明类

方面也可以声明类，这些会自动收集到 `den.classes` 中：

```nix
den.aspects.my-bundle = {
  classes.myapp = { description = "从方面声明的类"; };
};
```

方面声明的类通过 `aspect-schema.nix` 自动合并到 `den.classes`。

## 底层替代方案：`den.classes` + `route` 策略

除了使用 `den.batteries.forward` 电池，Den 还提供了更底层的 `den.classes` + `route` 策略方式。Den 内置的类（`os`、`user`）就是使用这种方式实现的：

```nix
{ den, ... }: {
  # 1. 注册类
  den.classes.files = { };

  # 2. 创建路由策略
  den.policies.files-to-flake-parts = _: [
    (den.lib.policy.route {
      fromClass = "files";
      intoClass = "flake-parts";
      path = [ "files" ];
    })
  ];

  # 3. 激活策略
  den.schema.flake-parts.includes = [ den.policies.files-to-flake-parts ];
}
```

这种方式更灵活但更底层，`den.batteries.forward` 是更便捷的封装。具体选择取决于你的使用场景。

## `den.batteries.forward`——构建转发方面

`den.batteries.forward` 是 Den 构建自定义类的便捷工具。它创建将类内容转发到目标类路径的方面：

```nix
{ den, lib, ... }:
let
  fwd = { host, user }:
    den.batteries.forward {
      each = lib.singleton user;
      fromClass = _: "container";
      intoClass = _: host.class;
      intoPath  = _: [ "virtualisation" "oci-containers" "containers" user.userName ];
      fromAspect = _: den.aspects.${user.aspect};
    };
in {
  den.schema.user.includes = [ fwd ];
}
```

### `forward` 参数

| 参数 | 描述 |
|---|---|
| `each = items` | 要转发的项目列表（通常是 `[ user ]` 或 `[ true ]`） |
| `fromClass = item: class` | 要读取的自定义类名 |
| `intoClass = item: class` | 要写入的目标类 |
| `intoPath = item: path` | 目标类中的目标属性路径 |
| `fromAspect = item: aspect` | 要读取自定义类的方面 |
| `guard = args: bool` | 仅当谓词返回 true 时转发 |
| `adaptArgs = args: attrs` | 转发前转换模块参数 |
| `adapterModule = deferredModule` | 转发子模块的自定义模块类型 |
| `evalConfig = bool` | 是否在转发前求值配置 |
| `mapModule = item: module -> module` | 对每个项目变换模块 |

## 转发模式

### 基础模式：从类 A 到类 B

这是最常见的模式——配置从自定义类转发到现有类：

```nix
den.aspects.alice.user = { pkgs, ... }: {
  packages = [ pkgs.hello ];
  extraGroups = [ "wheel" ];
};
```

`user` 类自动转发到主机 OS 类的 `users.users.alice`。这是通过 `os-user.nix` 实现的：

```nix
# 内置 user 类的实现
os-user = { host, user }:
  den.batteries.forward {
    each = lib.singleton user;
    fromClass = _: "user";
    intoClass = _: host.class;
    intoPath  = user: [ "users" "users" user.userName ];
    fromAspect = _: den.aspects.${user.aspect};
  };
```

### 别名模式：类到根路径

将一个类作为另一个类的别名：

```nix
hmAlias = { class, aspect-chain }:
  den.batteries.forward {
    each = lib.singleton class;
    fromClass = _: "hm";
    intoClass = _: "homeManager";
    intoPath = _: [ ];
    fromAspect = _: lib.head aspect-chain;
    adaptArgs = { config, ... }: { osConfig = config; };
  };
```

### 多目标模式：同时转发到多个类

```nix
# os 类同时转发到 nixos 和 darwin
os-class = { class, aspect-chain }: den.batteries.forward {
  each = [ "nixos" "darwin" ];
  fromClass = _: "os";
  intoClass = lib.id;
  intoPath = _: [ ];
  fromAspect = _: lib.head aspect-chain;
};
```

这在写入需要在 NixOS 和 Darwin 之间共享的配置时很有用：

```nix
den.aspects.my-laptop = {
  os.networking.hostName = "Yavanna";  # 同时应用于 NixOS 和 Darwin
};
```

## Guards（守卫）

Guard 控制条件类激活——只有当条件满足时才转发：

```nix
# 仅当目标有 wsl 选项时才转发
guard = { options, ... }: options ? wsl;

# 使用 mkIf 检查配置值
guard = { config, ... }: _item: lib.mkIf (config.programs.vim.enable);
```

两种形式的区别：
- 使用 `lib.optionalAttrs` 测试**选项是否被定义**
- 使用 `lib.mkIf` 测试**配置值**

### 平台条件转发

```nix
hmPlatforms = { class, aspect-chain }:
  den.batteries.forward {
    each = [ "Linux" "Darwin" ];
    fromClass = platform: "hm${platform}";
    intoClass = _: "homeManager";
    intoPath = _: [ ];
    fromAspect = _: lib.head aspect-chain;
    guard = { pkgs, ... }: platform: lib.mkIf pkgs.stdenv."is${platform}";
    adaptArgs = { config, ... }: { osConfig = config; };
  };
```

## Adapters（适配器）

适配器在转发过程中转换类内容：

```nix
persys = { class, aspect-chain }: den.batteries.forward {
  each = lib.singleton true;
  fromClass = _item: "persys";
  intoClass = _item: class;
  intoPath = _item:
    { config, ... }:  # 访问 intoClass 模块参数
    [ "environment" "persistance" config.impermanence.persistence-dir ];
  fromAspect = _item: lib.head aspect-chain;
  guard = { options, ... }@osArgs: options ? environment.persistance;
};

# 使用
den.aspects.my-laptop = {
  persys.hideMounts = true;
};
# 这变成：nixos.environment.persistance."/nix/persist/system".hideMounts = true;
```

### `adaptArgs`——参数适配

当目标类需要不同的参数名时：

```nix
adaptArgs = { config, ... }: { osConfig = config; };
```

### NVF（Nix Vim Framework）

```nix
{ inputs, ... }: {

```

## 多类方面

一个方面可以同时产生多个类的输出：

```nix
den.aspects.gaming = {
  nixos = { pkgs, ... }: {
    programs.steam.enable = true;
    hardware.opengl.enable = true;
  };

  homeManager = { pkgs, ... }: {
    programs.mangohud.enable = true;
  };

  user = { pkgs, ... }: {
    packages = [ pkgs.prismlauncher ];
  };
};
```

管道会自动将每个类键提取到相应的输出桶中。

## 碰撞处理策略（CollisionPolicy）

当一个方面提供的上下文参数与模块系统参数同名时，需要碰撞处理：

| 策略 | 行为 |
|---|---|
| `error`（默认） | 抛出错误，要求显式处理 |
| `class-wins` | 模块系统的参数胜出 |
| `den-wins` | Den 的上下文参数胜出 |

设置方式：

```nix
# 在 schema 级别
den.schema.host.collisionPolicy = "class-wins";

# 在实体级别
den.hosts.x86_64-linux.igloo.collisionPolicy = "class-wins";

# 管道值级别
den.lib.policy.pipelineOnly value
```

### 何时使用

- **`pipelineOnly`**：当值只应在管道中使用，不应与模块系统参数冲突时
- **`class-wins`**：当模块系统的 `lib`、`pkgs` 等参数应保持优先时
- **`den-wins`**：当 Den 的上下文（如 `host`、`user`）应覆盖同名模块参数时

## 完整示例：从简单转发到复杂自定义类

### 步骤 1：注册类

```nix
{ den, ... }: {
  den.classes.container = {
    description = "OCI 容器配置";
  };
}
```

### 步骤 2：创建转发

```nix
{ den, lib, ... }:
let
  containerForward = { host, user }:
    den.batteries.forward {
      each = lib.singleton user;
      fromClass = _: "container";
      intoClass = _: host.class;
      intoPath  = user: [
        "virtualisation" "oci-containers" "containers" user.userName
      ];
      fromAspect = _: den.aspects.${user.aspect};
      adaptArgs = { config, ... }: { osConfig = config; };
    };
in {
  den.schema.user.includes = [ containerForward ];
}
```

### 步骤 3：使用自定义类

```nix
den.aspects.alice = {
  container = { osConfig, pkgs, ... }: {
    image = "nginx:latest";
    ports = [ "8080:80" ];
    environment = {
      NGINX_HOST = osConfig.networking.hostName;
    };
  };

  # 仍然可以使用其他类
  homeManager = { pkgs, ... }: {
    home.packages = [ pkgs.docker-client ];
  };
};
```

### 步骤 4：高级——带守卫的类

```nix
{ den, lib, ... }:
let
  monitoringForward = { class, aspect-chain }:
    den.batteries.forward {
      each = [ "prometheus" "grafana" ];
      fromClass = lib.id;
      intoClass = _: class;
      intoPath = (tool: [ "services" tool ]);
      fromAspect = _: lib.head aspect-chain;
      guard = { options, ... }: tool:
        lib.mkIf (options ? services.${tool});
    };
in {
  den.schema.host.includes = [ monitoringForward ];
};
```

### 步骤 5：角色基础的动态类

```nix
roleClass = { host, user }: { class, aspect-chain }:
  den.batteries.forward {
    each = lib.intersectLists (host.roles or []) (user.roles or []);
    fromClass = lib.id;
    intoClass = _: host.class;
    intoPath = _: [ ];
    fromAspect = _: lib.head aspect-chain;
  };

den.schema.user.includes = [ roleClass ];

den.aspects.alice = {
  gaming = { pkgs, ... }: { programs.steam.enable = true; };
  devops = { pkgs, ... }: { virtualisation.podman.enable = true; };
};
```
